Episode 1 · Agno + Claude API

Morning Brief Agent: build guide

An agent that reads today's Google Calendar and Todoist to-dos and sends exactly five bullets to Telegram at 6:45 AM PHT. Track A sets up your accounts, keys and .env. Track B builds the agent in this repo, one TODO at a time, then schedules it. Commands are for Windows PowerShell.

Morning-Brief-Agent-Demopublic

Track A: set up the envs

About 45 minutes, most of it Google sign-in. You'll download the project, install its packages and collect your own keys in .env. Everything here is free except testing the Claude key, which costs a fraction of a cent.

A4 · Google Calendar sign-in · about 20 min

Google sign-in has four parts: a project, a consent screen, an OAuth client and one sign-in. Use the same Google account for all four: the one whose calendar you want in your brief. Google's console moves menus around; everything below lives under APIs & Services and Google Auth Platform.

A4.1

Create a project and turn on the Calendar API

  1. Open console.cloud.google.com. Click the project picker at the top → New project → name it morning-brief → Create.
  2. Check that the project picker now shows morning-brief. Every later step has to happen in this same project.
  3. Go to APIs & Services → Library, search for Google Calendar API, open it and click Enable.

✓ The Calendar API page shows Manage (or "API enabled") instead of Enable.

A4.2

Set up the consent screen

Google Auth Platform
  1. Go to APIs & Services → OAuth consent screen. It opens Google Auth Platform. Click Get started.
  2. App information: app name Morning Brief, and your email as the user support email. Next.
  3. Audience: External. Next.
  4. Contact information: your email. Next.
  5. Finish: tick the agreement → Continue → Create.
  6. Left menu → Data access → Add or remove scopes. Filter for calendar.readonly and tick .../auth/calendar.readonly. If it isn't in the list, paste https://www.googleapis.com/auth/calendar.readonly under Manually add scopes → Add to table. Then Update → Save.
  7. Left menu → Audience → Publish app → Confirm.

✓ Audience shows publishing status In production, and Data access lists the calendar.readonly scope.

Don't skip "Publish app". In Testing, Google expires the sign-in after 7 days and the brief stops on day 8. You don't need to submit the app for verification. For your own account, Google only shows an "unverified app" warning, which you click past in A4.4.

Prefer to stay in Testing? Then add your Gmail under Audience → Test users. If you don't, the sign-in shows "Access blocked". You'll also need to repeat A4.4 every 7 days.

A4.3

Create the OAuth client: choose Desktop app

Google Auth Platform → Clients
  1. Left menu → Clients → Create client. This opens the Create OAuth client ID page.
  2. Application type: open the dropdown and choose Desktop app. Web application is the wrong choice here.
  3. Name: Morning Brief desktop. Google shows this name only in the console.
  4. Use this client for an AI-powered agent: optional. Tick it if you see it (recommended). It labels the client as an AI agent's client, and it doesn't change what the client can read. Google requires the label only for its Workspace MCP servers. This project calls the Calendar API directly, so it works either way, and you can change the box later.
  5. Click Create.

✓ Right: Desktop app

Application typeDesktop app

NameMorning Brief desktop

Nothing else to fill in. No URI fields.

✗ Wrong: Web application

Application typeWeb application

NameWeb client 2

Authorized JavaScript originshttps://www.example.com

Invalid Origin: URI must not be empty.

Authorized redirect URIs…

Seeing "Authorized JavaScript origins", "Authorized redirect URIs" or "Invalid Origin: URI must not be empty"? Then Application type is still Web application, and the empty URI row you added causes the error. Switch the dropdown to Desktop app and the URI fields go away. Don't make the Web client work by typing in localhost addresses either: the script signs in the way a desktop app does, so a Web client fails later with redirect_uri_mismatch.

Download the JSON straight away. Right after Create, a dialog titled OAuth client created shows the client ID and secret. Click Download JSON before you close it. Google shows the full secret only once. If you closed the dialog without downloading, the quickest fix is to create another Desktop app client.

Then move the download into the project folder as credentials.json. This command takes the newest client_secret_….json in Downloads, so an older download can't sneak in:

Get-ChildItem "$HOME\Downloads\client_secret_*.json" | Sort-Object LastWriteTime -Descending | Select-Object -First 1 | Move-Item -Destination .\credentials.json -Force
(Get-Content credentials.json -Raw | ConvertFrom-Json).PSObject.Properties.Name

✓ The last line prints installed. If it prints web, the file came from a Web application client: go back to step 1 of A4.3.

Tidy up: on the Clients list, delete any Web application clients you made by mistake (such as "Web client 1" and "Web client 2"), so you can't download the wrong one later. Never commit credentials.json; .gitignore already excludes it.

A4.4

Sign in once and save token.json

python scripts\google_login.py
  1. A browser tab opens. Choose the same Google account you used in A4.1.
  2. Google hasn't verified this app: click Advanced → Go to Morning Brief (unsafe). This is normal for an app you made yourself.
  3. The permission screen asks to see and download any calendar you can access. This is read-only. Click Continue (or Allow).
  4. The tab says The authentication flow has completed. Close it. The terminal lists your calendars and saves token.json.
  5. Run the same command a second time.

✓ The second run lists your calendars without opening a browser. token.json works. Note the calendar id you want; primary is your main calendar.

Just created the client and sign-in fails with invalid_client? Google says client changes can take from 5 minutes to a few hours to apply. Wait a few minutes and try again. The script uses localhost:8080 for the sign-in. If port 8080 is busy (WinError 10048), close whatever is using it and rerun.

if len(brief.bullets) != 5:
    problems.append(f"expected 5 bullets, got {len(brief.bullets)}")

if sorted(kinds) != sorted(KINDS):

TODO 2.6

Refuse a broken run

main.py → check_run
if getattr(result, "status", None) == RunStatus.error:
    raise AgentRunFailed(f"agent run failed: {result.content}")
called = set()
for t in result.tools or []:
    called.add(t.tool_name)
    if t.tool_call_error:
        raise ToolFailure(f"{t.tool_name} raised an error")
    try:
        data = json.loads(t.result or "")
    except (TypeError, ValueError):
        continue
    if isinstance(data, dict) and "error" in data:
        raise ToolFailure(f"{t.tool_name} returned an error: {data['error']}")
missing = REQUIRED_TOOLS - called
if missing:
    raise ToolFailure(f"the agent never called {sorted(missing)}")

Agno doesn't raise errors itself. Without this check, an expired Google login turns into a confident "no meetings today".

4.3

Schedule it from your own private repo

GitHub Actions

Use your own private repo, not this public Demo repo. Anyone can read the workflow logs on a public repo, and you can't add secrets to a repo you don't own.

Install the GitHub CLI and sign in once with gh auth login. Then commit your work, create a private copy and push it:

git add -A
git commit -m "My Morning Brief agent"
gh repo create my-morning-brief --private --source . --remote mine --push

Give the private repo your keys, then send one brief from GitHub immediately:

$repo = "$(gh api user --jq .login)/my-morning-brief"
Get-Content credentials.json -Raw | gh secret set GOOGLE_CREDENTIALS -R $repo
Get-Content token.json -Raw | gh secret set GOOGLE_TOKEN -R $repo
gh secret set -f .env -R $repo
gh workflow run brief.yml -R $repo
gh run watch -R $repo

✓ The run finishes green, and a brief arrives in Telegram within about a minute.

Then turn on the daily run:

gh variable set MORNING_BRIEF_ENABLED --body true -R $repo

✓ From tomorrow, the brief arrives every day at 6:45 AM PHT.

.gitignore keeps .env, credentials.json and token.json out of the push. Your keys reach GitHub only through gh secret set, which stores them encrypted. In a new terminal, set $repo again before using it.
